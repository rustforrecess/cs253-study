Study Guide: Number Bases, Two’s Complement, Instructions & Bit Operations

Topics: writing numbers in different bases, two’s complement for signed values, shifts and bitwise operations, what a machine instruction is made of, and the ways an instruction can locate its operands. The practice game at the end covers everything on this page.

Key terms

Base (radix)The number of distinct digits a positional system uses. Base 10 uses 0–9; base 2 uses 0–1; base 5 uses 0–4.
Positional notationEach digit's value depends on its position: digit × baseposition, counting positions from 0 on the right.
Machine instructionA binary-encoded command the CPU can execute directly, made of an opcode and zero or more operands.
OpcodeThe part of an instruction that says what operation to perform (addu, lw, beq, …).
OperandThe part that says what to operate on — a register, a memory location, or a constant.
Addressing modeThe rule an instruction uses to figure out where an operand lives: in the instruction itself, in a register, in memory, etc.
Effective addressThe final memory address an instruction actually accesses, after its addressing mode has been applied.
Program counter (PC)The register holding the address of the next instruction to fetch.

Converting between bases

To read a number in any base, multiply each digit by that base raised to its position, then add. To go from base 10 to another base, repeatedly divide by the target base and collect remainders, reading them bottom-up.

Problem 2 · direct base 5 → base 2

Convert 2345 directly to base 2 — without going through base 10 as an intermediate answer.

Show worked solution
Divide the base-5 number by 2 in base 5 each time. The remainder is the next binary digit (least significant first): 2345 ÷ 2 = 1145 remainder 1 (bit 0 = 1) 1145 ÷ 2 = 325 remainder 0 (bit 1 = 0) 325 ÷ 2 = 135 remainder 1 (bit 2 = 1) 135 ÷ 2 = 45 remainder 0 (bit 3 = 0) 45 ÷ 2 = 25 remainder 0 (bit 4 = 0) 25 ÷ 2 = 15 remainder 0 (bit 5 = 0) 15 ÷ 2 = 05 remainder 1 (bit 6 = 1) Read bits bottom-up: 10001012 (same answer as Problem 1)

Note: base 5 isn’t a power of 2, so there’s no shortcut like grouping binary digits in threes for octal. Direct conversion here still means doing arithmetic in base 5 — the value never changes, only how it’s written.

Base-5 blocks: see the number

Each place value is a bundle of smaller pieces. In base 5, a unit is 1, a strip is 5 units, a flat is 5 strips (25 units), and a cube is 5 flats (125 units). Each place can hold at most 4 pieces before it rolls over into the next place up, just like base 10 holds at most 9.

Machine instructions

A machine instruction is a fixed binary pattern the CPU decodes. Its basic parts:

addu $10, $9, $8   (R-type, 32 bits)
+--------+-------+-------+-------+-------+--------+
| opcode |  rs   |  rt   |  rd   | shamt | funct  |
| 000000 | 01001 | 01000 | 01010 | 00000 | 100001 |
+--------+-------+-------+-------+-------+--------+
   6        5       5       5       5        6  bits
rs = $9 (source 1), rt = $8 (source 2), rd = $10 (destination)

Instructions with a constant, such as addi, use the I-type layout: opcode, rs, rt, then a 16-bit immediate in place of rd, shamt, and funct.

The CPU runs every instruction through the same fetch → increment → execute cycle: fetch the instruction at the address in the PC, increment the PC so it points to the next instruction, then execute the instruction (decoding its opcode and operands as part of that step). A jump changes the PC during execute instead of letting it advance by one instruction.

Addressing modes

The same opcode can find its operand in several different ways. The addressing mode tells the CPU which way applies. Using MIPS examples (lw loads a word from memory into a register):

ModeExampleWhere the operand comes from
Immediateaddi $t0, $zero, 5The value 5 is inside the instruction itself (a 16-bit immediate)
Direct (absolute)lw $t0, 1000($zero)The contents of memory address 1000. MIPS has no separate direct form for lw, so $zero (always 0) is the base
Registeraddu $10, $9, $8The contents of registers $9 and $8 (no memory access)
Register indirectlw $t0, 0($s0)Memory at the address held in $s0
Indexed / base+offsetlw $t0, 100($s0)Memory at address ($s0 + 100), good for array elements
PC-relativebeq $t0, $t1, 3Address = PC + 4 + 3 × 4. The green card writes this offset as OFF18, a 16-bit word offset shifted left 2

Two’s complement and signed numbers

With 8 bits, the unsigned range is 0 to 255. Two’s complement uses the same 8 bits for signed numbers from -128 to 127, and the leftmost bit has weight -128. A positive number keeps its unsigned pattern. To get the negative of a number, invert every bit and add 1.

Problem 3 · two’s complement of +45 and -45

Write 45 and -45 as 8-bit two’s complement patterns.

Show worked solution
+45: 45 = 32 + 8 + 4 + 1 = 00101101 (positive, so the pattern is unchanged) -45: start with 00101101 invert every bit 11010010 add 1 11010011 Check: weights -128, 64, 32, 16, 8, 4, 2, 1 1(-128) + 1(64) + 0(32) + 1(16) + 0(8) + 0(4) + 1(2) + 1(1) = -128 + 64 + 16 + 2 + 1 = -45 ✓

Shift instructions

sll d, s, shamt shifts bits left and fills the right side with 0s. srl d, s, shamt shifts bits right and fills the left side with 0s. A left shift by n multiplies by 2n. A logical right shift by n divides by 2n and drops the remainder, for values that are not negative. Both are R-type instructions, with opcode 000000. The funct field is 0x00 for sll and 0x02 for srl.

Problem 4 · two shifts in a row

$4 holds 5. Find $4 after sll $4, $4, 3, then find $4 after srl $4, $4, 2.

Show worked solution
5 = 00000101 sll 3: 00101000 = 40 (5 × 2³ = 40) srl 2: 00001010 = 10 (40 ÷ 2² = 10, remainder dropped)

Horner’s method in MIPS

Horner’s method evaluates a polynomial with one multiply and one add per term, by nesting the terms:

3x^4 - 2x^3 + 10x^2 - 13x + 14  =  ((((3)x - 2)x + 10)x - 13)x + 14

The MIPS program in HornersMethod.asm does this with mult and mflo. mult puts the full 64-bit product in the Hi and Lo registers, and mflo copies the low 32 bits into the destination register:

mult $10, $9        # $10 * $9 goes into Hi:Lo
mflo $10            # low 32 bits of the product go into $10

Worked example: multiply, then move the low word (newMult.asm)

This program computes 5x − 74 with x = 12. The multiply puts the product in Hi:Lo, and mflo copies the low word into a register:

ori    $8, $0, 12      # $8 = x = 12
ori    $9, $0, 5       # $9 = 5
mult   $9, $8          # Hi:Lo = 5 × 12 = 60
mflo   $9              # $9 = Lo = 60
addiu  $9, $9, -74     # $9 = 60 + (-74) = -14

After mult, Hi is 0 and Lo is 60, because the product is positive and fits in 32 bits. The final value in $9 is −14.

Overflow and trapping

A result overflows when it doesn’t fit in the register’s bits. With two’s complement, adding two positive numbers can produce a negative result, and adding two negative numbers can produce a positive one. The sign of the result is then wrong.

Problem 6 · 8-bit overflow

Add 01111111 (127) and 00000001 (1) in 8-bit two’s complement.

Show worked solution
01111111 (127) + 00000001 (1) = 10000000 reads as -128 The correct answer, 128, doesn’t fit in 8 bits. Two positive operands gave a negative result, so the sum overflowed.

Two MIPS instructions, two behaviors

add, addi, and sub check for overflow. If the result doesn’t fit in 32 bits, the CPU raises an arithmetic overflow exception (code 12 on the green card) and does not write the result. addu and addiu never check, so they wrap around silently. The same bits come out either way; the difference is whether the program is told.

# build 0x7FFFFFFF = 2147483647 in $8
lui    $8, 0x7FFF
ori    $8, $8, 0xFFFF
addi   $9, $0, 1

add    $10, $8, $9     # overflow: raises the exception, $10 is not written
addu   $11, $8, $9     # no check: $11 = 0x80000000 = -2147483648

The result of addu is wrong for 2147483647 + 1, and nothing in the program reports it. Use add when the program must catch overflow, and addu when wrapping is intended, as in hash functions and address arithmetic.
